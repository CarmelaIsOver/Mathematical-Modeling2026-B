# Q3联合调度优化：方案、自检与验收

本轮在原程序中接入新的问题三默认调度；200场独立同场对照平均改善10.29%，全部完成。问题四控制策略未改变，400秒/源仍是问题四尚未完成的目标。论文和旧ZIP未修改。

## 优化思路及最终取舍

人工日志指出一个具体问题：CUC5案例中的目标等待三站后被强制处理，一次前往目标、定位和清除共560.37秒，其中移动2.72公里。起终点之间本就很远，局部额外路程仅99米，因此先检验目标处理顺序比仅修改定位算法更有依据。这不是可直接省去560秒的证明。

考虑机器人当前在A、下一站B、目标估计位置C。途中处理C的新增移动时间可写成(AC+CB-AB)/5。最终实现将这个思想扩展为包含全部已发现目标和剩余站点的开放路线，而不只比较最近一个目标。目标位置使用观测约束区域的包围圆中心估计；这个中心用于调度，不替代清除时的安全几何判据。

每次得到新观测或完成清除后重新规划，只执行当前路线的首个任务。路线候选用八个近邻起点生成，并作有界次数的2-opt改进。等待期间经过搜索站点能够自然补充交叉方位，更新区域后路线也会改变；本轮没有另加未经标定的未来信息收益分数。

开发试验逐项比较：

| 40场开发方案 | 平均秒/源 |
|---|---:|
| 原策略 | 324.13 |
| 取消中途三站强制清除 | 295.00 |
| 再改进路线搜索 | 280.98 |
| 再跳过确定无用的已知目标测量 | **279.40** |
| 额外加入等待期间测量成本评分 | 280.78 |

最终采用前三项有效改动，未采用额外等待成本评分。这里的路线搜索是滚动启发式优化，不是完整POMDP，也不宣称动态TSP全局最优。

## 完整性自检

- 未知频道仍在完整七站覆盖中逐站测量，不根据发现数量达到10或连续无信号提前停止。
- 已发现目标一直保留在待清除集合中。每个正常决策至少访问一个新站点或完成一个目标；定位失败会进入既有后备或报错，不会虚报完成。
- 取消中途等待阈值后，搜索全部完成时仍逐个处理剩余目标。延后不会变成无限等待或漏清除。
- 仅当已知目标区域已经满足安全清除半径，或整个区域距当前测点均超过最大1500米接收半径，才跳过该测量。跳过后保留清除任务。
- 几何定位、清除证书、near处理、后备光学覆盖、协议计时与退出检查均沿用原实现。

开发种子2200000—2200039；查看独立结果前冻结候选tour_select、基线和代码SHA256，见protocol.json及frozen_sources.json。独立种子2300000—2300199，两策略使用完全相同的场景，共400次运行。控制器仅接收AuditPort接口，真实位置、数量只用于测试验收。

均值降低10.29%，P95降低9.78%；180场更快、1场持平、19场变慢。最差相对退化7.79%（种子2300196），没有退化超过10%的场景。配对平均节省32.36秒/源，场次bootstrap 95%区间为[28.82,35.97]。该区间针对本地生成器分布，不保证官方场景表现。

预设接入条件为全部完成、均值至少改善5%、P95不变差、退化超过10%的场景不超过5%；本轮全部满足，最差场景也完整保留。原始数据见holdout.csv/json和paired_analysis.json。

## 压力与接入检查

另设五类压力场景各20场：10目标、16目标、固定+1度测角误差、固定−1度误差、圆周边界目标，均用1000米最小接收半径。100场新策略与100场基线均全部完成；各组平均值均改善，单场最差相对退化8.47%。边界组平均仅改善约1.93%，表明收益并非对所有分布同样大。见stress.csv/json。

运行源码与冻结候选在三个开发场景的完整动作轨迹一致，冻结复现入口通过校验。自动检查包括未知频道完整扫描、已知目标任务保留、移除中途强制规则、覆盖后收尾及官方入口日志。仅用模拟后端测试官方入口，没有自动发起官方场次。

## 使用方式

问题三现在默认strategy=integrated、layout=original，JSON包含scheduling_policy=joint_route。显式standard仍可作同一入口中的历史对照，没有新增版本目录。

平台问题三演练就绪后，在成果/support执行：

```powershell
python run.py --mode official --problem 3 --robot-id $teamId --output practice_logs
```

冻结复现：`python verify_q3_scheduling.py --runs 200`。已有两份官方standard日志只能验证原策略，不是本轮新策略的人工验证。不能把这些日志的固定响应作为改变路线后的反事实反馈来宣称官方提速。
