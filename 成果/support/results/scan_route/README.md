# 搜索布局与扫描成本优化

本轮仅采用Q3七站 `hex` 布局：原点加半径1125米的正六边形，替代此前原点加半径1000米的七点环。保留adaptive定位及原路线算法；Q4继续使用rings/adaptive。本地两组独立配对共400场，Q3平均249.88→243.32秒/源，下降2.62%。未启动官方平台测试，未修改论文。

## 同场对照

| 数据集 | 场数 | 原tight/adaptive | 新hex/adaptive | 平均降幅 | P95原→新 | 全部清除 |
|---|---:|---:|---:|---:|---:|---:|
| 留出集4200000–4200199 | 200 | 250.38 | 244.87 | 2.20% | 315.99→305.74 | 200/200 |
| 最终复核4400000–4400199 | 200 | 249.37 | 241.77 | 3.05% | 313.31→298.85 | 200/200 |
| 两组合计 | 400 | 249.88 | **243.32** | **2.62%** | 见逐组数据 | 400/400 |

指标是逐场虚拟总时间除以源数，再对场次等权平均。原方案是用户最新测试的tight/adaptive，不是更早的原子定位。首组有133场更快，2场退化超过10%，最大退化14.80%；第二组147场更快，5场退化超过10%，最大退化12.71%。布局改善平均效率，不保证每场更快。

10000次场景自助重采样，两组合并后的新均值95%区间约240.00–246.64，同场节省时间区间5.24–7.90秒/源。该区间仅对应本地生成分布，不是官方成绩保证。用户刚提供的Q3两场259.04和Q4两场436.64属于修改前策略，不能计入本轮新布局的官方成绩。

平均每场测量121.46→110.71次，切频耗时113.77→104.16秒，移动2374.94→2358.62秒。主要收益来自少一次站点扫描带来的测量和切频减少，移动仅略降。不是单纯把固定巡回路线变短：七站固定开放巡回约6750米，反而比旧八站约6207米更长，必须以完整任务的实测成本判断。

## 连续覆盖证据

原点保证覆盖半径1000米以内的区域。对半径p处的外部点，1000≤p≤1800，其与最近六边形顶点的夹角不超过π/6，距离平方不超过

`p² + 1125² − 2 × p × 1125 × cos(π/6)`。

这个式子对p为凸函数，区间最大值在端点。p=1000和1800时，距离分别为563.09和999.11米，均严格小于保证接收半径1000米。因此外环与原点共同覆盖完整任务圆盘；没有通过漏扫边界换取时间。Q4有方向性，禁止采用这个仅适用于全向源的布局。

每组10个种子4300000–4300009，接收半径全部取1000米。50场新旧策略均完成：

|---|---:|---:|

| 固定+1°误差 | 260.40→260.40 | 1.0653 |
| 固定−1°误差 | 258.00→257.25 | 1.0834 |

10源与16源压力分组略有退化；边界组显著改善。采用依据是两个独立随机场景集都改善且平均低于250、覆盖有解析保证，并完整披露局部退化，不是所有压力分组都改善。

## 未采用的尝试

开发集固定4100000–4100023，共24场。Q3比较六点环1125米、1200米，以及给“先扫描后清除”增加成本的路线算法。1125米单独使用为246.34，相对基线252.16下降2.31%；配合路线调整为244.53，开发集更好，但留出集245.02没有优于单改布局244.87。因此采用更简单的布局改动，并另用4400000起的全新200场复核。按初始观测旋转布局也未优于固定七站，不采用。

减少光学搜索点没有自动缩短实际找到源的路径；优先清除虽然节省后续测量，也可能增加移动。候选均未接入Q4运行逻辑。

## 集成、测试和复现

61项测试全部通过，包括新布局连续覆盖上界、最差夹角边界源的正负极限测向误差、未知信道完整扫描和6场与冻结候选完全一致的动作序列。历史tight/adaptive及Q4的动作测试仍通过。最终复核首场的冻结源码复现与原始耗时和动作计数一致。

入口仍为 `成果/support/run.py`，当前默认Q3 `hex/adaptive`、Q4 `rings/adaptive`。`--layout tight` 可运行本轮修改前Q3；`--service-policy atomic` 保留更早的原子定位组合，不适合作为本轮布局唯一变化的对照。

```powershell
python -m unittest discover
python verify_scan_route_experiments.py --runs 1
# 完整复核200场
python verify_scan_route_experiments.py
```

本目录保存开发、留出、复核的逐场JSON和冻结源码；复现程序先校验每个源码文件SHA256，再在临时目录运行，避免当前代码改变历史实验。`integration.json` 保存统计、当前源码摘要与复现检查；`stress_cases.json` 保存压力测试；`adopted_trace_fixtures.json` 保存冻结动作摘要。

官方演练命令不变，先在平台启动相应场次后执行。新Q3启动行应显示 `layout=hex, service_policy=adaptive`；Q4仍为 `layout=rings, service_policy=adaptive`。后续需要多场官方实测验证本轮Q3布局。
