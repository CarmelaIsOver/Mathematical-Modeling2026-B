# Q3 250秒/源、Q4 440秒/源优化验收

本轮采用两问的自适应分步定位策略，已覆盖接入原来的 `support/run.py`。Q3在300个独立本地场景的样本均值为249.13秒/源；Q4最新200场为478.93秒/源，尚未达到440，但同场平均改善6.15%，按用户允许保留显著进展的要求采用。本报告不代表官方平台验收通过，未启动任何官方测试。

## 统计口径与结果

每场先计算虚拟总耗时除以源数量，再对各场等权取平均；包括移动、切频、测量、失败光学尝试和成功清除耗时。与基线使用相同场景种子，不以界面起止时间或程序计算时间代替指标。基线为本轮修改前的Q3 tight原子定位、Q4 radial原子定位。

| 独立对照 | 场数 | 原方案均值 | 采用方案均值 | 平均降幅 | 原P95→新P95 | 新方案全部清除 |
|---|---:|---:|---:|---:|---:|---:|
| Q3，3800000–3800299 | 300 | 256.56 | **249.13** | 2.89% | 315.43→309.98 | 300/300 |
| Q4，3600000–3600199 | 200 | 510.29 | **478.93** | 6.15% | 655.27→612.53 | 200/200 |

时间单位均为秒/源。Q3有268场更快，166场单场≤250，最大同场退化5.64%；Q4有169场更快，77场单场≤440，3场退化超过10%，最大退化33.86%。平均改善不能解释成每一场改善。

Q4同一候选此前在3300000–3300199的200场为468.86；与本轮合计400场，原均值505.30，新均值473.90，降幅6.22%，160场≤440。此前200场不是本轮新测试；合并结果用于说明收益在第二组种子上得到复核。

对独立场景进行10000次自助重采样：Q3新均值95%区间为244.94–253.40，同场节省时间区间为6.51–8.35；Q4最新200场新均值区间为465.78–492.05，同场节省区间为26.85–35.83。这些区间只反映本地生成分布。**Q3样本均值达标，但尚不能断言其总体均值稳定低于250，更不能据此保证官方实测达标。**

## 实际修改

1. 将定位拆成有限的观测步骤。得到一次有效测向后，把尚未清除的源保留在全局任务集合，重新规划搜索点和已知源的访问顺序。每源最多四次部分推进，之后回到原完整定位流程；不会把尚未清除的任务当作完成。
2. Q3保存未收到信号的位置。对全向且尚未清除的源，该观测意味着源在保证接收半径1000米之外。用外凸包收缩现有可行域，保留所有可能连通分量，并设置数值余量。Q4可能因波束方向收不到信号，禁止使用这项距离排除。
3. Q3在小可行域内增加有限的中心光学尝试；失败后继续定位，不把尝试当作清除成功。已发现16个源时取消剩余发现站，但必须清除全部16源才能退出。发现阶段结束后仍对剩余目标规划路线。
4. Q4采用已验证覆盖的22点rings布局，结合分步定位；增加已有测向几何选点器提供的候选观测点。没有降低最终清除判据，也没有用离线真值做在线决策。

控制器新增逻辑集中在 `localization_service.py`，由 `omni_search.py` 和 `joint_search.py` 接入。入口默认 `service_policy=adaptive`。`--service-policy atomic` 可在同一套代码中选择修改前基线：Q3 tight，Q4 radial；`--service-policy atomic --layout rings` 可单独比较布局收益。没有新增并行运行版本目录，没有修改论文。

## 验证与复现

58项测试全部通过，涵盖原布局覆盖、官方接口记录和计时、负观测几何包含性、有限分步回退、全源完成与默认入口。6条完整动作序列摘要与冻结候选逐条一致。两问各复现一个最终独立集场景，虚拟耗时、清除数、测量数和失败数均与保存结果一致。

在 `成果/support` 中运行：

```powershell
python -m unittest discover
python verify_target_pair_experiments.py --problem 3
python verify_target_pair_experiments.py --problem 4
```

复现脚本校验冻结源码摘要，在临时目录运行原始实验，避免后续代码变动影响历史比较。可用 `--runs 1` 做短复现。`final_holdout_q3*.json`、`holdout_q4*.json` 保存逐场结果、协议、汇总及冻结源码；`adopted_trace_fixtures.json` 为最终采用候选动作摘要；`integration.json` 保存集成源码摘要、重采样统计和复现检查结果。

官方演练仍使用原命令；先在平台分别启动对应问题的演练，再运行对应命令：

```powershell

python run.py --mode official --problem 3 --robot-id $teamId --output practice_logs
python run.py --mode official --problem 4 --robot-id $teamId --output practice_logs
```

启动行应分别显示 `layout=tight, service_policy=adaptive` 和 `layout=rings, service_policy=adaptive`。客户端明文日志与平台导出的行为日志应配套保留。官方分布与本地生成器可能不同，最终判断需补充多场实际演练。
