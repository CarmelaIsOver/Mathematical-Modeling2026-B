# 效率优化验收报告

本报告分两轮。第一轮按动态任务路线与POMDP有限前瞻实现原型，未达采用门槛，不进入默认算法。第二轮改为压缩覆盖站布局，问题3的新布局达到门槛并成为默认，问题4的22站布局在平均提速一项上仍未达标，需单独判断。

采用门槛在实验前固定，两轮相同：相对现行策略平均至少提速5%，P95不增加，慢超过10%的场景不超过5%，样本内最差耗时比不超过1.20，且全部配对运行完整清除。

## 第二轮：覆盖站布局压缩

两问都是移动主导：问题3约78%、问题4约71%的仿真时间花在移动。因此本轮不再改调度，而是直接压缩必须走完的覆盖站巡回。

### 问题3：tight 八站布局（已采用为默认）

原布局为原点加半径1558.85米的正六边形共7站。但接收只在1000米内有保证，因此覆盖条件仅为“目标区域每点距某站不超过1000米”。取原点加半径1000米的正七边形共8站即可满足，且巡回更短。

闭式证明：设点的极径为 p，与最近辐条的夹角为 phi，则 |phi| <= pi/7。原点在 p <= 1000 时覆盖该点；由余弦定理，到该辐条站点的距离满足 d^2 = p^2 + 1000^2 - 2000 p cos(phi)，故 d <= 1000 等价于 p <= 2000 cos(phi)。该界在 |phi| = pi/7 时最紧，

    2000 cos(pi/7) = 1801.938 米 > 1800 米，

因此整个目标区域被覆盖，最紧的点是 pi/7 方向的边界点，距站点 998.2545 米。这是精确结论，不是抽样验证。原点不可省：七个环上站点距原点恰为1000米，去掉原点后圆心不再有保证覆盖。原点本身不额外花费，机器狗从该处出发。

自原点出发的开放巡回由9353米降为6207米。

### 问题4：rings 22站布局（默认，但平均提速未达门槛）

问题4的覆盖条件更强：定向源只在其半平面内可收，故每点必须落在“距其1000米以内的站点”的凸包内。已在库中并已验证的22站环形布局（原点、半径999米7站、半径1870米14站）取代25站radial布局。

问题4的边界环无法再压缩，这是几何结论：半径1800米处朝外辐射的源只能在圆域之外被接收，因此8、10、12、14站的外环巡回长度都在11.6至12.0千米之间。仅覆盖内部的条带布局能证明半径1600米以内被覆盖，但始终无法覆盖边界。对环形与混合布局的搜索最低到17581米，但需26站，多出的检测耗时超过1.7%的巡回收益。外环半径1850米是能通过证明的下限（1845米不通过），所省0.75%不值得贴近边界。

## 本轮已实现但不采用的候选

以下四项均已实现、已在配对种子上测量、随后全部回退，代码不保留。记录原因以免重复。

1. 自适应覆盖记账。在某点把当时全部未知频道测完后，即可把该点计入覆盖，再据此裁掉冗余覆盖站。证书本身正确，并独立复现了库中已有的全部四种布局。结果：问题3仅提速0.22%而计算量增至20倍；问题4的输出与rings逐条相同，其19站来自已有的16源取消规则而非裁剪。原因是已压缩的布局余量太小，随机落点的清除点几乎不可能覆盖掉一整个站点。此项最接近所给三篇论文的cautious greedy思路，在本题条件下并不划算。
2. 精测点改以当前位置为基准。慢1.2%。原判断有误：原有的 p0 + 0.8d 已在上次观测点到区域中心的八成处，那段移动本就是朝目标接近，不是折返。再加上按后验收缩排序也未能挽回（慢1.28%）。
3. 覆盖顺序优先内圈，使后续站点的未知频道更少。机制如预期生效，检测时间降5.08%，但移动时间升13.20%，40场中22场慢超过10%。内圈优先破坏了巡回几何。
4. 外环半径压到1850米以下。1845米无法通过覆盖证明。

一个通用结论：本题移动结构占主导，任何以扰动巡回换取检测节省的改动都会亏。改路线前应先与目标点加站点的联合TSP下界比较——问题3实走13270米对下界11713米，问题4实走21459米对下界19657米，路线启发式已无多少余量。

## 正确性与检查

新增 test_coverage_tight.py，用三条互相独立的途径验证问题3新布局：geometry.py中的闭式界、不依赖该代数的密集极坐标扫掠、以及就地写出的连续四叉树细分。三者一致，且扫掠找到的最紧点与代数预测的998.2545米相符。

注意 coverage_geometry.certify 只实现问题4的凸包条件，对问题3这一规模的全向布局一律返回False，包括原有的original布局；用它检查问题3布局属于用错判据。

测试总数由39项增至48项，全部通过。其中问题3、问题4默认入口的策略与布局断言已随默认值更新。
